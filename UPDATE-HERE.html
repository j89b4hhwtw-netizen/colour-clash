This updates your existing game. Keep the same Supabase project, GitHub repository and website address.

Keep your existing config.js. This download does not include a replacement, so your connection settings stay in place.

1. Finish current games

Ask everyone to finish or leave their current room. Install the update, then create a new room so it uses the corrected cards and new settings.

2. Update Supabase

  1. Open your existing Colour Clash project in Supabase.
  2. Open SQL Editor → New query.
  3. Click Copy full SQL update below. Paste it into the query.
  4. Click Run. Wait for a success message. This updates the existing game functions; do not delete your project or tables.
Show SQL / copy manually

You can also open setup.sql with Notepad, select all and copy it. Run the complete file, from “begin” to “commit”.

3. Upload the update to GitHub

  1. Extract this ZIP and open the colour-clash-update folder.
  2. Open your existing colour-clash GitHub repository.
  3. Choose Add file → Upload files.
  4. Drag the files inside the update folder into GitHub, not the folder or ZIP itself.
  5. Click Commit changes. GitHub replaces the matching filenames.

The updated website files are index.html, app.js, style.css, sw.js and manifest.webmanifest. It is also fine to upload the included SQL, README and guides.

Keep your existing config.js, supabase.js, icons and licence file. There is no need to change your API key.

4. Open the updated game

  1. Wait until GitHub Pages finishes its deployment.
  2. Open your usual game link. On Windows, press Ctrl + F5 to reload. On your phone, close and reopen the game; refresh again if it still looks old.
  3. Create a new room. Select Regular or No Mercy, jump-in and double play.
  4. If you choose No Mercy, you will see Eliminate at 25 cards. Leave it unchecked for no 25-card elimination, or tick it to enable that rule.
  5. Invite everyone. In the lobby, the host uses the ↑ / ↓ buttons under each player to choose the order. Player 1 starts.

What you will see

  • Redesigned cards with large numbers, clearer action symbols and corner values.
  • Each player's name above a face-down hand, with their exact card count below. A fan shows up to five decorative backs; the number is the real total.
  • A highlight on the current player and a warning when someone has one card.
  • A numbered starting order. Jump-ins resume from the jumper; reverse, skip and elimination continue to affect play.
  • Taking a + card penalty ends your turn. You cannot immediately jump in after taking that penalty until another card is played.
  • Drawing one normal card in Regular still allows you to play that drawn card if it matches.
  • No fixed player cap in the code. Very large rooms still depend on devices and your Supabase plan.

Card ratios and deck size

The game adds whole decks, keeping the same proportion of every card. It starts with enough cards for seven each, plus roughly seven each in reserve. It reshuffles discards first; if every available card is held, it adds a complete extra deck with fresh card IDs.

The earlier No Mercy mix has been corrected. Example starting sizes: 2 players use 108 / 168 cards; 15 players use 216 / 336; 40 players use 648 / 672 (Regular / No Mercy).

If you get an error

“Function not found” or “Unknown action”: run the whole SQL update in the same Supabase project used by your existing config.js, then reload the website.

Old cards or missing options: check that GitHub's latest Pages deployment has completed and that the files were uploaded at the repository root. Refresh the game and create a new room.

“The room changed”: another player acted first. Wait for the screen to refresh, then try again.
